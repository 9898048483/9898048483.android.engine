## 🏗️ 10. APK Signature Schemes (v1, v2, v3) Deep-Dive

Android package authenticity is guaranteed through a multi-tier cryptographic signing process applied to `signed-release.apk`:

```text
+--------------------------------------------------------------------------------+
|                         ZIP Central Directory Format                           |
+--------------------------------------------------------------------------------+
|  1. ZIP Entries / Data Payloads (classes.dex, resources.arsc, assets)          |
+--------------------------------------------------------------------------------+
|  2. APK Signing Block (Magic: "APK Sig Block 42")                              |
|     ├── ID 0x7109871a (Scheme v2 Block: ECDSA P-256 + X.509 Certificate)       |
|     └── ID 0xf05368c0 (Scheme v3 Block: SDK 34 Lineage Proof & Key Rotation)   |
+--------------------------------------------------------------------------------+
|  3. Central Directory (CD File Headers)                                        |
+--------------------------------------------------------------------------------+
|  4. End of Central Directory Record (EOCD with updated CD offset pointer)       |
+--------------------------------------------------------------------------------+
```

1. **Scheme v1 (JAR Manifest Verification)**:
   - Each individual file inside the ZIP archive is hashed (SHA-256) into `META-INF/MANIFEST.MF`.
   - `META-INF/CERT.SF` contains manifest section digests.
   - `META-INF/CERT.RSA` encapsulates the PKCS#7 signed signature block.
2. **Scheme v2 (Whole-File ECDSA Verification)**:
   - Divides the entire APK binary (excluding the Signing Block itself) into 1MB chunks.
   - Computes a Merkle tree root hash across sections 1, 3, and 4.
   - Signs the Merkle root with ECDSA P-256 / SHA-256, protecting against any bit-level tampering.
3. **Scheme v3 (Target SDK 34 & Key Rotation Lineage)**:
   - Identical whole-file cryptographic security to v2 with added support for cryptographic signing certificate rotation lineages, ensuring continuous seamless Google Play / enterprise sideload updates across API levels 26–34.
